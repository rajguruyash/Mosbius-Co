    WHAT IT ACTUALLY DOES

    The agents you already have.

    Mosbius & Co does not ship a model. It drives the CLIs on your machine.

    Finds your CLIs

    Claude Code, Codex and Gemini CLI are detected where they are installed. Nothing is installed for you, and nothing signs in on your behalf.

    IN THE APP

    A session per agent

    Each agent runs in its own terminal, with its own working directory and its own history, whichever room it sits in. Changing room never stops a session.

    IN THE APP

    Agent manager

    Hire, name and place agents, watch what each is doing, and stop any of them from one window.

    IN THE APP

    MCP servers

    The seven local servers run on your computer and need no account; hosted ones connect with your sign-in, a key, or an OAuth app you register. Every one is off until you switch it on, and an agent reaches it only through a local broker, with access you grant per agent and per tool.

    IN THE APP

    REST integrations

    Ready-made templates (nine, one of them for any base URL of your own) behind a local broker. Your key is encrypted by the operating system and attached at call time, never handed to the agent, and each request is checked by method and path.

    IN THE APP

    Skills

    Browse a catalogue of community skills, see the source repository, install the ones you want by hand, for Claude Code or for Codex and Gemini CLI. Nothing installs itself, an installed skill grants nothing and connects nothing, and an update shows every changed line before anything changes.

      Switch a server on, add its key if it needs one, and give Ted access — only then is he handed the connection. Until all three are true he is not given it at all, rather than given one that fails.

      Each room has its own crew, and every agent reads the same catalogue. Keys are encrypted by your operating system and never reach the agent or the interface; the app hands a key only to the server or request it belongs to.

      What the words mean

      Nothing on, until you say so. Every server starts switched off. Switching one on only makes it available: each agent then needs access of its own, and the default is none. Files and git are pinned to the workspace, never your whole disk.
      Reading and acting are separate. Access is read, write or a hand-picked list of tools. A tool that sends, posts or deletes — or that nobody has classified yet — is never included by read or write; you tick it by name.
      No real account has been used. The local servers answered real calls on a Mac. Every sign-in and key flow was run against a stand-in service. So no account-based provider is marked verified, and one can still fail at its first real call.
      Hosted Google and Slack need your own app. They refuse the on-the-spot registration an agent depends on, so Mosbius reaches them with an OAuth app you register yourself and sign in to once. On the default engine their tokens sit in readable files while an agent that uses them runs: that is a known limit, listed under Security.
      SKILLS

      Skills, installed by hand.
      They grant nothing.

      A skill is a folder of instructions an agent can load. The Skills tab lists a community catalogue, shows the source of each entry, and installs only when you press Install. The app does not vouch for what is in the catalogue; it makes sure that installing a skill cannot give it power.

      Discover and install

      Browse the catalogue, see the source repository, install for the agent CLI you choose. Nothing installs itself and nothing updates by itself.

      IN THE APP

      Installing grants nothing

      A skill never gives itself an integration permission and never connects a service. The integrations it needs show up as dependencies, each with its own Connect button, and each still needs your grant.

      IN THE APP

      Filtered on the way in

      Tool grants, hooks, servers and permission modes are taken out of the copy, run-on-load commands are defused, and configuration that would arm a hook or a server is not written at all. Scripts are written as plain, non-executable files and listed to you.

      IN THE APP

      Provenance and integrity

      Every install records its source and the exact commit it was read at, plus a hash of every file, in a record the agent cannot edit. Check tells you if anything changed on disk, file by file.

      IN THE APP

      Updates and rollback

      An update is fetched into a staging folder and shown to you line by line, with any new script or integration, before anything changes. The old version is kept, so you can roll back.

      IN THE APP

      Per-agent installation

      Claude Code reads its own folder; Codex and Gemini CLI read a shared one. Each target has its own record, so a skill can be installed for one, updated for another, and removed from a third.

      SECURITY AND PERMISSIONS

      Who can reach what.

      Mosbius decides, on every single request, which agent may use which tool. The default is none, and the person at the keyboard is the only one who can change it. The limits are listed here as plainly as the controls.

      1. 1 · Switch it on. Every integration starts off. Switching one on only makes it available.
      2. 2 · Connect it. Sign in on the service's own page, or store a key. The agent never sees either.
      3. 3 · Grant that agent access. None, read, write, or a hand-picked list of tools, with an optional end time.

      Deny by default

      A new agent can reach nothing. A tool nobody classified is treated as destructive and is never in read or write.

      Per agent, per tool

      Read, write and destructive are separate. A tool that sends, posts or deletes is ticked by name, never included for you.

      A pass, not your login

      An agent holds a random pass for a single integration, which only works on this computer's loopback address and which the app can cancel at any moment.

      Revoked at once

      Taking access away applies to the agent's next request and cancels the ones in flight. Revoking in the middle of a run was tested through the real Codex and Gemini CLIs.

      Credentials stay put

      Keys and tokens live in the operating system's encrypted store, are handed only to the local server they belong to, over a private pipe, and never reach the agent, the page, a log or a process listing.

      An audit trail

      Every decision is written to a hash-chained record of names and decisions, never contents or secrets. A deleted, truncated or edited record is detected.

      Local servers are isolated

      Installed from version-pinned, hash-checked locks with install scripts off, run by the app rather than by the agent, and the file and git servers are scoped to the workspace.

      Known limits

      The full list, with what was tested and how, is in the security report.
