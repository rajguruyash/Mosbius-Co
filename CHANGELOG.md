# Changelog

Changes to Mosbius & Co.

## [Unreleased]

### Added

- **Seven locations.** Ted's apartment, MacLaren's (entered from the street), GNB, the rooftop, Barney's apartment, Columbia and the laser tag arena, all original pixel art. Switch with the tabs above the floor or keys 1 to 7.
- **A team per location.** Each location has its own boss and roster. An agent joins the location that is open when you add it, and keeps running wherever you look.
- **Doors and transitions.** Agents walk between locations through the doors; changing location opens like a pair of doors, and the pub is entered from the street.
- **MacLaren's is a basement bar.** From the street you go down a flight of steps, behind green wrought-iron railings, to a green half-glazed door below the pavement, warm light spilling up. The old corner entry at the bottom left is gone: the pub has the one way in. The app and the website draw the same artwork, railings included.
- **The cast.** Ted, Marshall, Lily, Robin, Barney, Tracy, Penny, Luke, Ranjit, Carl, Wendy, the GNB staff and more.
- **First launch.** A pixel photo album, Ted's welcome and a plain-language workspace picker.
- **Dark theme by default**, a Ted app icon and a Mac DMG build.
- **Settings → Integrations & Skills.** Five tabs: Discover (every service and how it connects), Connected (on or off, which tools each may use, disconnect), Skills, Agent access (one table of who may use what, none by default) and Activity (the tamper-evident record). In English, Simplified Chinese and Arabic, right to left. See `INTEGRATIONS.md`.
- **Sign in with your account.** Notion, Linear, Sentry, Stripe and Atlassian connect with no key to paste: the app registers itself for one sign-in (RFC 7591), you approve on the service's own page (PKCE, loopback redirect), and Disconnect revokes it (RFC 7009). GitHub connects with a sign-in code (RFC 8628). Built and tested against a stand-in; **no real account has been signed in to yet**, and every card says so.
- **Codex CLI and Gemini CLI agents reach integrations.** Each CLI is handed its pass its own way (a config file for Claude Code; the broker address on the command line and one variable for Codex; a settings file naming one variable for Gemini). All three were run for real (Codex 0.142.2 and Gemini CLI 0.68.0 with a stand-in model and provider, no account): see `evidence/codex/codex-live.json` and `evidence/gemini/gemini-live.json`. The Gemini run found that the first design could never have loaded on that version (it wrote a system settings file, which Gemini refuses unless root owns it), and that the broker turned Gemini away as a "browser" because Node's own `fetch` adds `Sec-Fetch-Mode: cors`; both are fixed. Gemini's shell can read its agent's pass and no Gemini setting can stop that: closing it was attempted and measured, and left open on purpose (finding F9, with the three reasons in `SECURITY_REPORT.md`). Codex's shell cannot while Codex's OS sandbox is on, and Claude Code's cannot (its pass is in a file under deny-read rules).
- **Skills, managed.** Install for Claude Code or for Codex and Gemini CLI (they read different folders), see where each came from down to the commit, check whether it still matches, preview every changed line of an update before anything changes, and roll back. Installing a skill grants nothing and connects nothing. See `SKILLS.md`.
- **A support matrix that cannot overclaim.** `INTEGRATIONS.md` is generated from the data the app uses, and a test fails if they disagree. `VERIFIED` needs an evidence file in the repository.
- **Documents and website generated from the app's own data.** `tools/lib/catalogue.cjs` derives one catalogue from the files the app itself uses (the provider manifest, the MCP catalogue, the REST templates, the agent compatibility table, the English locale, the world file and the `evidence/` runs): every provider with how it connects and how far it was checked, the three coding agents with the version that was run and its recorded checks, the locations, and every count. `npm run docs:gen` writes the generated tables of `README.md` and `INTEGRATIONS.md` from it and `npm run website:build` writes the website's data; each has a `--check` mode that CI runs. The status vocabulary is six words with one meaning each (Implemented, Locally tested, Stand-in tested, Real-account verified, Not yet verified, Not implemented), derived by a written rule, and nothing can be called locally tested or real-account verified without an evidence file in the repository.
- **A website that says what the product does, and stops where the evidence stops.** New sections for the three coding agents (what was run for each, and the weaknesses measured: Codex's protection needs its sandbox, Gemini's shell can read its pass), every integration grouped by what it is for with its state in the six words, the skills platform, who can reach what with the known limits, five real captures of the settings interface (copied byte for byte from the packaged-app run, never mocked up) and an honest status table. Counts in its prose are generated, a sentence that calls an account-based provider verified fails the build, and the build runs the page's own scripts against the data to read what a visitor would get. The page keeps its look, layout, animations and the existing sections.
- **`website/` is under version control.** It was never committed, although the room and sprite exporters write into it and three tests already read it, so those tests could not pass on a fresh clone.
- **Tests:** `test/catalogue.test.cjs` (every provider is documented, statuses follow from evidence, counts agree with the data), `test/website.test.cjs` (the build in check mode, the page as rendered, and that each check catches what it is for), `test/ci-workflows.test.cjs` and `test/lockfile-sync.test.cjs` (below). The existing test that the landing page names Gmail, Calendar, Drive and Slack as needing your own OAuth app now reads the generated catalogue instead of typed names, and asserts the same things.
- **Checks you can run:** `tools/verify-codex-live.cjs` and `tools/verify-gemini-live.cjs` (the real Codex or Gemini CLI against the broker, with a stand-in model and provider), `tools/verify-claude-skills-live.cjs`, `tools/ui-validate.cjs` (the real desktop app, driven, with screenshots) and `tools/gen-support-matrix.cjs`.

### Changed

- **`README.md` rewritten** to describe what is in the `main` branch, with the status of every capability stated in the six words above, the limits listed instead of hidden (Gemini's shell can read its pass, Codex's protection needs its sandbox, the `mcp-remote` bridge's readable token files), what is not built said so (there is no control to move an agent between locations yet), and the platforms that were never run on hardware labelled.
- **CI:** the workflows use actions that run on Node 24 (checkout and setup-node v7, upload-artifact v7, github-script v8) instead of Node 20, which GitHub deprecated for actions. This is the runtime of the actions only; the `node-version` the jobs ask for, for the project's own tooling, is unchanged. A job checks that `README.md`, `INTEGRATIONS.md` and the website match the app (`docs:check`, `website:check`); every job has a time limit; `platforms.yml`, which builds unsigned installers and keeps them for a week, now runs only when started by hand.
- **Settings → Connections** keeps the manual options (your own sign-in app and the choice of sign-in engine); the rest moved to **Integrations & Skills**.
- **Status text is readable in the dark theme.** The app already asked for `--cth-danger` and `--cth-mint-700` but never defined them, so error and success text fell back to dark colours on the dark surface (as low as 1.02:1). Both are defined for both themes; the new page measures 5.47:1 or better.

- **Every MCP server is opt-in.** The six that used to start with the app (Sequential Thinking, Filesystem, Git, Fetch, Time, Context7) are now off like the rest. Switching one on only makes it available: each agent also needs access of its own, and the default is none, set per agent and per tool. Upgrading switches those six off once; a server you switch on afterwards stays on.
- **The app runs the local MCP servers, not the agent.** An agent's `mcp-config.json` holds a loopback address and a capability for that one agent and server, and nothing else: no command, argument, environment variable or key. Each server is installed from a version-pinned lock with hashes (`npm ci --ignore-scripts`, or `uv pip install --require-hashes --no-deps --no-build`), refused if it does not match, and runs as a child of the app. The `mcp-remote` bridge for Gmail, Calendar, Drive and Slack is unchanged and is still the default engine for those four.
- **A key reaches its server over a private pipe**, not through its environment or arguments, which other processes of the same user can read on macOS.
- **REST integrations are grant-based.** An agent has no access until you grant it, and a grant is judged request by request, by method and path (a GraphQL request counts as read only if its document is a query).
- **Settings → Connections** shows each local server's pinned package and whether it is installed, and an Access panel for every server: per agent, per tool, with an optional end time.
- The old live check `tools/verify-mcp-live.cjs` is retired, because it verified the earlier design. `tools/verify-stage-b-live.cjs` and `tools/verify-packages-live.cjs` replace it.

### Security

- **Codex does not keep a pass out of the shell it runs for the model by default**, and its shell snapshot puts the whole environment back into every command. For a Codex agent that has an integration the app now turns the snapshot off and excludes its own variable names, keeping your own exclusions. Measured on Codex 0.142.2, with a control. For those agents Codex re-reads your login shell for each command.
- **A provider that rotates refresh tokens no longer breaks when two sign-in engines share a store.** The store is re-read before a grant is declared dead.
- **Nothing is reachable until switched on, and the upgrade keeps it that way:** the six local servers that used to ship on are switched off once, and a switch you made yourself is left alone (checked in the real app).

- **Secrets out of `config.json`.** The Slack signing secret and bot token, the Groq key, the org-trigger key and every webhook secret now live in the operating system's encrypted store. They are migrated with a write-then-verify step, and the interface only ever learns whether one is set.
- **A tamper-evident activity log.** Every access decision is appended to a hash-chained log that rotates, with its newest end sealed separately, so a deleted, truncated, rolled-back or edited log is detected.
- **Skills cannot arm themselves.** Installing a skill removes `allowed-tools`, `hooks`, `mcpServers` and `permissionMode` from its markdown, defuses run-on-load `!` commands and writes no hook, server or plugin configuration. Nothing it ships is executed or installed; scripts and dependency files are written as non-executable data and listed for you.

### Fixed

- **CI stopped at `npm ci`**: "`npm ci` can only install packages when your package.json and package-lock.json are in sync. Missing: ws@8.23.0 from lock file". `openai@6.44.0` (pulled in by `@openai/agents-core`) declares `ws ^8.18.0` as an *optional* peer dependency; the lock held `ws@7.5.11`, hoisted for another package, which does not satisfy it. An optional peer is not installed by itself, but once something in the tree resolves it the version must satisfy the range, so `npm ci` wanted a second copy, `ws@8.23.0`, that the lock did not list. The lock was regenerated with `npm install --package-lock-only` (no hand edits; `package.json` dependencies unchanged; it now also records the root package under its current name). `test/lockfile-sync.test.cjs` runs `npm ls --package-lock-only --all` and `npm ci --dry-run` offline, and fails on the old lock with the same messages CI gave.

- **The test suite could not run on Node 20**, the version CI's jobs use. `pixi.js` reads the global `navigator` while it loads, and Node 20 has none (Node 21 added it), so `test/sprite-export.test.cjs` crashed on load. The shared loader (`test/load-ts.cjs`, which `tools/export-sprites.cjs` also uses) now defines a minimal `navigator` only where it is missing. Found by running the whole suite from a fresh clone of the commit on Node 20.20.2 with npm 10.8.2, the combination `setup-node` gives for `node-version: 20`.
